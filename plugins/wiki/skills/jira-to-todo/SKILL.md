# Jira 잔여 이슈를 오늘의 TODO에 기록하기

Jira를 읽어 오늘 Daily 노트의 `# TODO` 섹션을 최신으로 맞춥니다. 하루에 여러 번 다시 실행해도 됩니다.
매 실행마다 아래 세 단계를 순서대로 합니다. Jira는 읽기만 하고 수정하지 않습니다.

1. 노트에 있는 Jira 항목의 상태를 맞춥니다.
2. 조회 범위의 새 이슈를 추가합니다.
3. TODO에 있는 Jira 항목(2단계에서 넣은 항목 포함)의 하위 이슈를 추가합니다.

이 순서라야 한 번 실행한 직후 다시 실행해도 바뀌는 것이 없습니다.

## 노트 확인

- 사용자의 현지 날짜를 확인하고 `~/wiki/Journal/Daily/YYYY-MM-DD.md` 노트를 엽니다.
- Daily 노트가 없거나 정확히 `# TODO`인 제목이 없으면 사용자에게 알리고 멈춥니다. Daily 노트나 섹션을 새로 만들지 않습니다.
- Jira 연동 도구(예: Atlassian MCP)가 없으면 연결이 필요하다고 알리고 멈춥니다.
- 노트 전체에서 Jira 키를 모읍니다. Jira 링크·URL(`/browse/ABC-123`) 속 키는 항상 키로 봅니다.
  `[RD-180]`처럼 본문에만 있는 `ABC-123` 형태는 Jira에서 조회될 때만 키로 봅니다.
- 모은 키는 `key in (...)` JQL 한 번으로 읽습니다. 키마다 따로 조회하지 않습니다.
- 필드는 `summary`, `status`, `assignee`, `parent`, `duedate`, `resolutiondate`만 요청합니다. 그래도 응답이 크면 키와 이 필드만 추려 읽습니다.

## 1. 상태 맞추기

`# TODO` 섹션 안의 Jira 항목 줄마다 Jira의 현재 상태로 고칩니다.

Jira 항목 줄은 키가 있는 체크박스 줄입니다. 키가 체크박스 없는 링크·URL 줄에만 있으면 바로 위 체크박스 줄을 그 키의 항목 줄로 봅니다.
위 줄도 체크박스가 아니면 노트를 고치지 않고 상태만 보고합니다.

| Jira 상태 | 노트 처리 |
| --- | --- |
| Done 범주 | `[x]`로 체크하고 상태 표시를 지웁니다. 노트가 `✅ YYYY-MM-DD` 완료 날짜를 쓰면 Jira 해결일(`resolutiondate`)을 붙입니다 |
| Backlog·To do | 상태 표시를 지웁니다 |
| 그 밖의 상태 | 요약 뒤 상태 표시를 `(현재 상태)`로 바꾸거나 붙입니다 |

- 노트에서 `[x]`인데 Jira가 Done이 아니면 체크를 풀지 않고 불일치로 보고합니다.
- 고치는 범위는 체크 상태, 상태 표시, 완료 날짜뿐입니다. 요약 텍스트, 링크, 들여쓰기는 그대로 둡니다.
- 완료 날짜는 줄 끝에 붙이되, `^abc123` 같은 블록 ID가 있으면 그 앞에 붙입니다.
- `# TODO` 섹션 밖에서 언급된 Jira 키는 노트를 고치지 않고 현재 상태만 보고합니다.

## 2. 새 이슈 추가

인자에 따라 범위를 정합니다.

| 인자 | 조회 |
| --- | --- |
| 없음 | 모든 프로젝트에서 `assignee = currentUser() AND statusCategory != Done` |
| 보드 URL 또는 프로젝트 키 | 그 프로젝트에서 `assignee = currentUser() AND statusCategory != Done` |
| 에픽·상위 이슈 키 | 그 이슈의 하위 이슈 중 내 담당인 미완료 이슈 |

- 인자가 없거나 프로젝트 단위일 때는 Backlog가 아닌 이슈와 기한이 7일 이내이거나 지난 이슈만 넣습니다. 나머지 Backlog 이슈는 몇 건인지만 보고합니다.
- 보드 URL의 보드 필터는 직접 읽을 수 없을 수 있습니다. 그럴 때는 URL의 프로젝트 키로 조회하고, 보고할 때 그 사실을 밝힙니다.
- 하위 이슈가 없는 상위 이슈의 진행 단계를 펼쳐 달라는 요청이면 이슈 본문의 TODO 목록과 최신 코멘트에서 단계를 읽습니다. 완료된 단계는 `[x]`로 적습니다. 본문에 없는 단계를 지어내지 않습니다.

## 3. 하위 이슈 추가

`# TODO`에 있는 Jira 항목의 하위 이슈(서브태스크, 에픽 자식)를 `parent in (...)` JQL 한 번으로 찾습니다.

- 내 담당이고 Done 범주가 아닌 이슈를 Backlog까지 모두 넣습니다. 상위 항목이 TODO에 있다는 것은 그 묶음 전체를 챙긴다는 뜻이기 때문입니다.
- 그 항목 줄 아래에 한 단계 들여써서 넣습니다.
- 다른 사람 담당 이슈는 넣지 않고 보고에서 건수만 언급합니다.

## 기록 형식

모든 단계에서 노트에 이미 있는 Jira 키는 다시 넣지 않습니다.

```md
# TODO
- [ ] {기존 할 일}
- [ ] {요약} — [KEY-1](https://{사이트}/browse/KEY-1)
- [ ] {상위 이슈 요약} — [KEY-2](https://{사이트}/browse/KEY-2)
    - [ ] {하위 이슈 요약} (In Progress) — [KEY-3](https://{사이트}/browse/KEY-3)
    - [ ] {하위 이슈 요약} — [KEY-4](https://{사이트}/browse/KEY-4)
- [ ] {하위 이슈가 없는 상위 이슈 요약} — [KEY-5](https://{사이트}/browse/KEY-5)
    - [x] {본문 TODO·코멘트에서 읽은 완료 단계}
    - [ ] {본문 TODO·코멘트에서 읽은 남은 단계}
```

- 요약은 Jira 제목을 짧게 줄여도 됩니다.
- 상태가 Backlog·To do가 아니면 요약 뒤에 `(In Progress)`처럼 상태를 붙입니다.
- 같은 상위 이슈의 하위 이슈가 둘 이상이면 위처럼 상위 이슈 줄 아래에 들여써서 묶습니다. 상위 이슈가 이미 TODO에 있으면 그 줄 아래에 넣습니다.
- 들여쓰기 문자(탭·공백)는 노트의 주변 항목을 따릅니다.
- Jira 기한이나 우선순위는 적지 않습니다. 보고에서만 언급합니다.
- `# TODO`에 실제 할 일이 있으면 그 뒤에 추가하고, 내용 없는 `- [ ]` 자리표시자만 있으면 첫 할 일로 바꿉니다.
- TODO 섹션 밖의 내용과 Jira 키가 없는 기존 항목은 수정하지 않습니다.

## 다시 실행한 예시

실행 전:

```md
# TODO
- [ ] 회의록 정리
- [ ] 검색 랭킹 개선 — [KEY-2](https://{사이트}/browse/KEY-2)
    - [ ] 피처 추가 (In Progress) — [KEY-3](https://{사이트}/browse/KEY-3)
    - [ ] 오프라인 평가 — [KEY-4](https://{사이트}/browse/KEY-4)
- [x] 인덱스 재색인 — [KEY-5](https://{사이트}/browse/KEY-5)

# 메모
- KEY-9 배포 일정 확인 필요
```

Jira 현재 상태: KEY-3 Done, KEY-4 In Review, KEY-5 In Progress, KEY-9 In Progress.
KEY-2 아래에 내 담당 KEY-6(In Progress)이 새로 생겼고, 다른 프로젝트에 내 담당 KEY-7(In Progress)이 있습니다.

실행 후:

```md
# TODO
- [ ] 회의록 정리
- [ ] 검색 랭킹 개선 — [KEY-2](https://{사이트}/browse/KEY-2)
    - [x] 피처 추가 — [KEY-3](https://{사이트}/browse/KEY-3)
    - [ ] 오프라인 평가 (In Review) — [KEY-4](https://{사이트}/browse/KEY-4)
    - [ ] 온라인 실험 설정 (In Progress) — [KEY-6](https://{사이트}/browse/KEY-6)
- [x] 인덱스 재색인 — [KEY-5](https://{사이트}/browse/KEY-5)
- [ ] 캐시 TTL 조정 (In Progress) — [KEY-7](https://{사이트}/browse/KEY-7)

# 메모
- KEY-9 배포 일정 확인 필요
```

- KEY-5는 노트에서 `[x]`지만 Jira는 In Progress이므로 그대로 두고 불일치로 보고합니다.
- KEY-9는 `# TODO` 밖이므로 고치지 않고 상태(In Progress)만 보고합니다.

## 완료 보고

- 바뀐 항목(키, 전 → 후)과 추가한 항목을 표로 보여 주고 Daily 노트 경로를 밝힙니다.
- 넣지 않은 이슈를 이유별 건수로 적습니다(이미 있음, Backlog, 다른 담당자).
- 노트와 Jira가 어긋난 항목을 알립니다. 노트 `[x]`인데 Jira 미완료, 상위 이슈는 Done인데 하위 이슈가 열린 경우 등입니다. Jira 상태는 바꾸지 않습니다.
- `# TODO` 밖에서 언급된 키의 현재 상태를 적습니다.
- 기한이 지났거나 오늘인 이슈를 알립니다.
