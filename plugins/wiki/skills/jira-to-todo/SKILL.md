# Jira 잔여 이슈를 오늘의 TODO에 기록하기

Jira에서 내 미완료 이슈를 읽어 오늘 Daily 노트의 `# TODO` 섹션에 추가합니다. Jira는 읽기만 하고 수정하지 않습니다.

## 노트 확인

- 사용자의 현지 날짜를 확인하고 `~/wiki/Journal/Daily/YYYY-MM-DD.md` 노트를 엽니다.
- Daily 노트가 없거나 정확히 `# TODO`인 제목이 없으면 사용자에게 알리고 멈춥니다. Daily 노트나 섹션을 새로 만들지 않습니다.
- Jira 연동 도구(예: Atlassian MCP)가 없으면 연결이 필요하다고 알리고 멈춥니다.

## 조회 범위

인자에 따라 범위를 정합니다.

| 인자 | 조회 |
| --- | --- |
| 보드 URL 또는 프로젝트 키 | 그 프로젝트에서 `assignee = currentUser() AND statusCategory != Done` |
| 에픽·상위 이슈 키 | 그 이슈의 하위 이슈 전부(담당자 무관) |
| 이미 TODO에 있는 항목 | 그 항목에 연결된 Jira 키의 하위 이슈 전부 |
| 없음 | 어느 프로젝트인지 먼저 묻고 파일을 수정하지 않습니다 |

보드 URL의 보드 필터는 직접 읽을 수 없을 수 있습니다. 그럴 때는 URL의 프로젝트 키로 조회하고, 보고할 때 그 사실을 밝힙니다.

## 고르기

- 노트에 이미 있는 Jira 키(링크 또는 본문 속 키)는 다시 넣지 않습니다.
- 프로젝트 단위로 조회할 때는 진행 중인 이슈(Backlog가 아닌 상태)와 기한이 있는 이슈만 넣습니다. 나머지 Backlog 이슈는 넣지 않고, 몇 건인지만 보고합니다.
- 에픽·상위 이슈 단위로 조회할 때는 내 담당인 미완료 하위 이슈를 넣습니다. 다른 사람 담당 이슈는 넣지 않고 보고에서만 언급합니다.
- 하위 이슈가 없는 상위 이슈의 진행 단계를 펼쳐 달라는 요청이면 이슈 본문의 TODO 목록과 최신 코멘트에서 단계를 읽습니다. 완료된 단계는 `[x]`로 적습니다. 본문에 없는 단계를 지어내지 않습니다.

## 기록 형식

- 각 이슈를 `- [ ] <요약> — [KEY](https://<사이트>/browse/KEY)` 형식으로 적습니다. 요약은 Jira 제목을 짧게 줄여도 됩니다.
- 상태가 Backlog·To do가 아니면 요약 뒤에 `(In Progress)`처럼 상태를 붙입니다.
- 같은 상위 이슈의 하위 이슈가 둘 이상이면 상위 이슈 줄 아래에 들여써서 묶습니다. 상위 이슈가 이미 TODO에 있으면 그 줄 아래에 넣습니다.
- 들여쓰기 문자(탭·공백)는 노트의 주변 항목을 따릅니다.
- Jira 기한이나 우선순위는 적지 않습니다. 보고에서만 언급합니다.
- `# TODO`에 실제 할 일이 있으면 그 뒤에 추가하고, 내용 없는 `- [ ]` 자리표시자만 있으면 첫 할 일로 바꿉니다.
- TODO 섹션 밖의 내용과 기존 항목의 텍스트·체크 상태는 수정하지 않습니다.

## 완료 보고

- 추가한 항목을 표로 보여 주고 Daily 노트 경로를 밝힙니다.
- 넣지 않은 이슈를 이유별 건수로 적습니다(이미 있음, Backlog, 다른 담당자).
- 기한이 지났거나 오늘인 이슈를 알립니다.
- 상위 이슈는 Done인데 하위 이슈가 열려 있으면 불일치로 알립니다. Jira 상태는 바꾸지 않습니다.
